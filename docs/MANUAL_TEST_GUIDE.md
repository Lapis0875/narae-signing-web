# 나래 서명 MVP 수동 테스트 가이드

## 1. 범위

이 문서는 이미 준비된 **로컬 테스트 환경**에서 현재 MVP의 화면 흐름을 확인하는 운영자용 체크리스트다. 스택 기동, 프록시 구성, 데이터베이스 직접 수정은 이 문서의 범위가 아니다.

Task30의 동시성·경합 게이트 완료 여부를 이 가이드로 주장하지 않는다. 아래 절차는 화면과 API가 연결된 정상 흐름을 수동으로 확인하는 데만 사용한다.

## 2. 안전한 사전 조건

- 운영 환경과 분리된 테스트 데이터와 테스트 관리자 계정을 사용한다.
- 시작 전에 담당자가 제공한 HTTPS `APP_PUBLIC_ORIGIN`을 확인한다. 현재 Compose 소스는 프런트를 `http://localhost:${FRONTEND_PORT:-8080}`에 노출하지만, 관리자·서명 세션과 CSRF 쿠키가 `Secure`이므로 이 HTTP 주소로 로그인 시험을 하지 않는다.
- 브라우저에는 `APP_PUBLIC_ORIGIN`과 같은 HTTPS 주소만 입력한다. 이 문서는 고정 포트를 가정하지 않는다.
- 로컬 HTTPS가 자체 서명 인증서를 쓴 경우에만 브라우저 경고가 나타날 수 있다. 테스트용 localhost 인증서인지와 주소가 `APP_PUBLIC_ORIGIN`과 일치하는지를 확인한 뒤 진행한다. 운영 인증서 경고를 우회하지 않는다.
- 테스트 시작 전 `GET /health`가 HTTP `200` 및 `{"status":"UP"}`인지 확인한다. 실패하면 수동 테스트를 시작하지 말고 환경 담당자에게 전달한다.
- 관리자 자격 증명은 안전한 별도 채널에서만 받거나 생성한다. 비밀번호, 쿠키, CSRF 토큰, 공유 토큰을 문서·채팅·스크린샷·커밋에 기록하지 않는다.

## 3. 관리자 로그인과 보드 목록

1. HTTPS `APP_PUBLIC_ORIGIN`에 접속한다. 로그인 화면의 제목은 `관리자 로그인`이다.
2. 테스트 관리자 이메일과 비밀번호를 입력해 `로그인`한다.
3. 성공하면 `/boards`의 `보드 목록`으로 이동한다. 보드가 없으면 `아직 만든 보드가 없습니다.`가 표시된다.
4. `목록 새로고침`으로 목록을 다시 읽는다.

기대 결과:

- 로그인 성공: 보드 목록이 표시된다.
- 잘못된 자격 증명: `로그인에 실패했습니다. 이메일과 비밀번호를 확인해 주세요.`가 표시된다.
- 반복 실패로 제한됨: 같은 메시지와 함께 남은 대기 시간이 표시될 수 있다. 추가 추측 입력을 중지한다.
- 세션이 만료됨: 다시 로그인 화면으로 이동하거나 `세션이 만료되었습니다. 다시 로그인해 주세요.`가 표시될 수 있다.

## 4. 보드 만들기와 기본 편집

1. `새 보드 만들기`를 누른다.
2. `보드 제목`에 테스트용 제목을 입력하고 `보드 만들기`를 누른다.
3. `보드를 만들었습니다.` 토스트가 표시되고 `/boards/{boardId}/edit` 편집 화면으로 이동하는지 확인한다.
4. 상단 제목을 바꾼 뒤 `제목 저장`을 누르고 새 제목이 유지되는지 확인한다.
5. 필요하면 `보드 목록`으로 돌아가 새 보드의 상태와 제목을 확인한다.

오류 시에는 생성 화면의 `보드를 만들지 못했습니다. 다시 시도해 주세요.` 또는 화면의 오류 토스트가 표시될 수 있다. 제목, 상태, 소유자 같은 서버 관리 필드를 브라우저 개발자 도구나 직접 API 호출로 바꾸지 않는다.

## 5. 명단, 캔버스, 배경

편집 화면의 `명단 편집`에서 다음을 확인한다.

1. 이름을 포함한 테스트 명단 한 건을 직접 추가한다. 성공 토스트는 `명단을 추가했습니다.`다.
2. 필요하면 명단을 수정·삭제하고 각각 `명단을 수정했습니다.`, `명단을 삭제했습니다.`가 표시되는지 확인한다.
3. 미배치 명단의 이름을 클릭하거나 캔버스로 끌어 서명 칸을 배치한다. 자동 저장 상태가 `저장 중`을 거쳐 `저장됨`이 되는지 확인한다.
4. 배치된 칸을 이동하거나 크기를 조절한 뒤 새로고침한다. 최신 위치가 다시 표시되는지 확인한다.
5. `PNG 또는 JPEG` 배경 파일을 선택한다. `기존 비율로 교체` 또는 확인 후 `이미지 비율 적용`을 사용한다. 성공하면 `배경을 교체했습니다.` 토스트와 새 배경이 표시되어야 한다.

명단 파일 가져오기와 서버 명단 교체도 필요할 때만 테스트한다. 지원 파일은 CSV와 XLSX이며, 성공 토스트는 각각 `파일 명단을 가져왔습니다.`, `서버 명단으로 갱신했습니다.`다. 실패하면 기존 서버 명단이 유지되고 입력 오류 행 또는 오류 토스트가 표시되어야 한다.

저장 충돌이 발생하면 자동 저장 상태가 `저장 실패`가 되고, 작업자가 입력한 배치 값은 편집 중인 화면에 유지된다. 오류 토스트는 `서버 배치와 충돌했습니다. 최신 상태를 불러왔습니다.`다. 자동 병합이나 재배치를 기대하지 말고, 화면에서 원하는 배치인지 확인한 뒤 작업자가 직접 다시 저장한다.

## 6. 공유, 전체보기, 서명 상태

1. `공유` 패널에서 서명 링크와 QR이 보이는지 확인한다. `링크 복사`가 실패하면 `링크를 복사하지 못했습니다. 주소를 직접 선택해 복사해 주세요.`가 표시될 수 있다.
2. 링크를 재발급하려면 경고 내용을 확인하고 `재발급`으로 확정한다. 기존 링크는 즉시 무효화된다. 성공하면 `공유 링크를 재발급했습니다.` 토스트가 표시된다.
3. `전체보기`를 열어 배경, 배치된 칸, 제출 상태가 보이는지 확인한다. 불러오지 못하면 `전체보기를 불러오지 못했습니다.`가 표시된다.
4. 상단의 `서명 시작`을 눌러 상태가 `서명 진행`이 되는지 확인한다. 이후 `마감`은 `마감/보관`, `다시 열기`는 다시 `서명 진행`으로 바꾼다.
5. `마감/보관` 상태에서만 `최종 PNG 다운로드`가 활성화된다. 내려받은 파일이 비어 있지 않은 PNG인지 확인한다. 실패 시 `최종 PNG를 다운로드하지 못했습니다.`가 표시된다.

## 7. 공개 서명 제출

1. 다른 브라우저 프로필 또는 시크릿 창에서 현재 공유 링크 `/sign/{shareToken}`를 연다. 공개 서명 화면은 짧은 화면에서 지원하지 않으므로 최소 가로·세로 중 작은 값이 600px 이상인 태블릿 크기로 연다.
2. 보드가 `설정 중`이면 `아직 서명 준비 중입니다. 잠시 후 다시 확인해 주세요.`가, 마감이면 `서명이 마감되었습니다.`가 표시되는지 확인한다.
3. 열린 보드에서 조직, 직책, 이름을 입력하고 `정보 확인`을 누른다. 이름을 비우면 `이름을 입력해 주세요.`가 표시된다.
4. `서명 패드`에 한 번 이상 서명한 뒤 `서명 제출`을 누른다. 성공하면 서명 입력 화면이 완료 화면으로 전환되고 `이미 서명을 제출했습니다. 감사합니다.`가 계속 표시된다.
5. 관리자 창의 편집 화면 또는 `전체보기`에서 해당 명단이 `제출`로 갱신되는지 확인한다.

공개 링크가 무효이면 `이 링크에서는 서명을 진행할 수 없습니다.`, 식별 정보가 만료되면 `서명 정보를 다시 입력해 주세요.`, 제출 실패면 `서명을 저장하지 못했습니다. 다시 시도해 주세요.`가 표시될 수 있다. 이 상태에서 공유 링크·서명 세션 값을 복사하거나 보관하지 않는다.

## 8. 정리와 재설정

- 테스트가 끝나면 테스트 보드 편집 화면에서 `보드 영구 삭제`를 누르고 경고를 읽은 뒤 `영구 삭제`로 확정한다. 보드와 모든 서명은 되돌릴 수 없다.
- 테스트 관리자 계정, 브라우저 저장 데이터, 테스트 파일은 팀의 승인된 로컬 환경 정리 절차로만 제거한다. 운영 데이터나 다른 테스트 스택을 대상으로 일괄 삭제하지 않는다.
- 공유 링크를 재발급했다면 이전 링크가 더 이상 사용되지 않는지 확인하고, 테스트 링크를 티켓·채팅·문서에서 제거한다.

## 9. 실패 기록과 전달

문제를 전달할 때 다음만 기록한다.

- 발생 시각과 재현 단계
- 화면 경로(예: `/boards/{boardId}/edit` 또는 `/sign/{shareToken}`에서 식별자는 마스킹)
- Network 탭의 요청 경로와 HTTP 상태
- 응답 헤더의 `X-Request-ID` 또는 JSON 오류의 `requestId`
- 사용자에게 보인 오류 문구, 브라우저·화면 크기, 마스킹된 스크린샷

다음은 기록하거나 첨부하지 않는다: 쿠키, 세션 ID, CSRF 토큰, Authorization 값, 요청·응답 본문, 비밀번호, 실제 이름·조직·직책, 원본 서명 데이터, 공유 토큰.
